# SX-0001 discovery: Java Pet Store Lite

**Verdict.** This is one small J2EE 1.3 web application, `legacy-source/j2ee-pet-store-lite`: 42 Java classes, 20 JSPs, about 14,100 text lines across 132 kept files. Around it sit a Derby/Oracle schema, six Control-M batch jobs and three user/operator guides. Business behaviour falls into three areas: **catalog** (browse, search, data integrity), **sample data population**, and **sign-on** (registration, authentication, lockout, roles, audit). The highest-risk area is sign-on. Its rules are split across Java constants, DDL, batch SQL, config and the guides, and several of those sources disagree (F1 to F16 below). No requirements were extracted at this stage.

Every path below is relative to `legacy-source/`.

**Screens (17 user-facing pages, all owned by `src/main/webapp`).** There are 15 `*.screen` definitions: main, category, product, item, search, signon, signon_welcome, signon_error, signon_locked, user_creation_error, signoff, account, access_denied, populate_admin, general_error. There are also 2 standalone pages, `index.jsp` and `populating.jsp`. Non-screen endpoints: `j_signon_check` (handled by the filter), `/createuser.do`, `/signoff.do`, `/Populate`.

**Stack.** Servlet 2.3, JSP 1.2 and JSTL 1.0, JDBC through JNDI `jdbc/CatalogDB`, Derby 10.14 (Oracle 19c DDL as reference). It has no Struts, no EJB, no JMS and no `validation.xml`. In the playbook's reading order, the declarative layer is `web.xml`, `signon-config.xml`, `screendefinitions_en_US.xml`, `CatalogDAOSQL.xml` and `PopulateSQL.xml`. Validation is programmatic only (`CreateUserServlet.validate`).

## 5. Dependency graph (see `dependency-graph.json`)

There are 35 nodes (21 modules, 9 database objects, 5 external) and 74 edges. The structure in short:

- `web.xml` wires the encoding filter, the sign-on filter (on `/*`), the template servlet (`*.screen`), registration, sign-off and populate.
- Catalog reads the six catalog tables through `CatalogDAOSQL.xml`. Populate drops, creates and loads all eight tables through `PopulateSQL.xml`. Sign-on reads and writes `signon` and `signon_audit`.
- Control-M schedules `batch/*.sh`, which source `conf/env.sh` and run `db/batch/*.sql`. `PSL_CATALOG_CHECK` calls back into the web tier over HTTP (`/Populate`). That edge is what makes F3 reachable from a batch job.
- The nightly chain: `PSL_DB_BACKUP` 01:00, then `PSL_AUDIT_EXTRACT` 01:30, then `PSL_SIGNON_REPORT` 01:45 and `PSL_AUDIT_PURGE` (Sundays 02:00). `PSL_CATALOG_CHECK` runs independently at 06:00, and `PSL_ACCT_UNLOCK` runs every 15 minutes.

## 6. Exclusions and coverage

- **At extract time** (from `excluded.md`): 990 files dropped. That is 672 VCS metadata files, 118 media and font files, and 200 binary files by content sniff. The media includes the 16 guide screenshots and the PDF guides the README mentions; the HTML source of each guide is kept. The catalog images under `src/main/webapp/images` were dropped too, which is why `item.jsp` image paths point at missing files. No requirement depends on them.
- **Excluded at discovery, not sharded:**
  - `vortex/expected-extraction.md`, `vortex/planted-findings.md`: these describe what a correct extraction should find. They were **deliberately not read**, so discovery and extraction stay independent evidence. Extraction agents must not read them either; they are for grading by a human.
  - `vortex/README.md`, `vortex/build-inputs.sh`: harness upload steps, not application behaviour (not read beyond file names).
  - `vortex/inputs/**`: byte-identical copies of `db/schema/*`, `scheduler/control-m/PSL_PETSTORE.xml` and `vortex/samples/*`. The `petstore.properties` copy differs only in redaction-token numbering. Extract from the originals.
  - `README.md`, `LICENSE-SUN.txt`, `.gitignore`: descriptive or legal, no behaviour. The README's capability table was used only for orientation.
  - `src/main/webapp/WEB-INF/c.tld`, `fmt.tld`: vendor JSTL descriptors (inside the `src/main/webapp` module but carry no rules).
- **Redactions.** Values replaced with `«REDACTED:secret-finding-N»` include the password minimum and maximum lengths and several `web.xml` env-entry values (DAO class, SQL URL, dialect). Where a rule depends on a redacted value, extraction must cite the non-secret corroborating source (the JSP hint text, the guides) or raise an ambiguity, never guess.
- **Coverage.** All 132 kept files were listed. Every non-excluded file belongs to exactly one module row, except that `src/main/webapp` is the parent path of the separate `src/main/webapp/populate` row; the `src/main/webapp` shard should skip `populate/`. Discovery read the declarative configuration, all DDL, the batch and scheduler files, and the sign-on, populate and catalog-DAO Java in full. The `waf` template framework and the individual XML populators were only skimmed.

3. Job details

3.1 PSL_DB_BACKUP

Online backup of PetStoreDB with SYSCS_UTIL.SYSCS_BACKUP_DATABASE (db/batch/db_backup.sql). The backup is moved to /var/petstore/backup/PetStoreDB_YYYYMMDD. Backups older than 7 days are deleted. Critical job: up to 2 reruns 10 minutes apart; on failure Control-M mails psl-ops and PSL_AUDIT_EXTRACT stays waiting.

3.2 PSL_AUDIT_EXTRACT

Exports yesterday's rows of SIGNON_AUDIT (00:00 to 24:00) to /var/petstore/extract/signon_audit_YYYYMMDD.csv for the security team (db/batch/audit_extract.sql).

ColumnContent
1 audit_idEvent number
2 usernameUser name as typed
3 event_typeSIGNON_OK, SIGNON_FAIL, SIGNON_LOCKED, ACCOUNT_LOCKED, ACCOUNT_UNLOCKED, SIGNOFF, USER_CREATED
4 event_tsTime of the event
5 remote_addrClient address, or batch:PSL_ACCT_UNLOCK

No header row. The last line is a trailer TRAILER,YYYYMMDD,<row count>; the count excludes the trailer.

3.3 PSL_SIGNON_REPORT

Writes yesterday's counts per event type, the number of locked accounts and accounts per role to /var/petstore/extract/signon_report_YYYYMMDD.txt.

3.4 PSL_AUDIT_PURGE

Sundays only. Deletes SIGNON_AUDIT rows older than 90 days. It waits for that day's extract so no row is deleted before it is extracted.

3.5 PSL_CATALOG_CHECK

Runs catalog checks C1 to C4 (see the Administrator Guide). If the catalog tables do not exist it calls http://localhost:8080/petstore/Populate?forcefully=false to load the sample data, then checks again. Exit code 4 means a check found rows; Control-M mails psl-catalog. Details are in /var/petstore/log/catalog_check.log.

3.6 PSL_ACCT_UNLOCK

Every 15 minutes. Unlocks accounts locked more than 30 minutes ago, resets their failed attempts and writes ACCOUNT_UNLOCKED to the audit.

4. Exit codes and recovery

CodeMeaningAction
0OKNone
4PSL_CATALOG_CHECK found bad catalog dataCatalog team fixes the data or an administrator reloads the sample data. Rerun the job.
8SQL or file errorRead batch.log and the job log. Check that Tomcat is up (the Derby network server runs inside it) and that port 1527 answers. Rerun.

4.1 Restore from backup

  1. Stop Tomcat.
  2. Move /var/petstore/db/PetStoreDB aside.
  3. Copy /var/petstore/backup/PetStoreDB_YYYYMMDD to /var/petstore/db/PetStoreDB.
  4. Start Tomcat and open the store home page.

4.2 Rerunning the extract

The extract always covers the day before the run date. To re-extract an older day, run the export query in db/batch/audit_extract.sql by hand with the dates changed.
